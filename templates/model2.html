Model 2 · Binary Programming — Limited Additional Capacity

max Σc,k wc ack yck   subject to   Σ yck ≤ B,   yck ≤ yc,k−1,   Σc∈p yck ≤ Mp,   yck ∈ {0, 1}
① DECISION VARIABLE
what we choose
For each possible extra section: open it, or not?
y = 1 open it y = 0 do not
Yes/no only — this is the binary (0-1) model.
② OBJECTIVE
what we optimise
Seat as many students as possible with the sections we have.
maximise Σ w · (students seated)
Every student counts the same.
③ TARGET
the rule we must obey
Use no more than {{ budget }} extra sections.
Σ y ≤ {{ budget }}
The budget is the knapsack; each candidate section is an item.

Constraints — the rules the solution must obey

# Constraint In symbols What it means How many
C1 Stay inside the budget Σ y_ck ≤ {{ budget }} All the extra sections you open, added together, cannot exceed the budget. This is the constraint that actually bites: the solver used {{ s.extra_sections_used }} of {{ budget }}. 1
C2 Open sections in order y_ck ≤ y_c,k−1 You cannot open a course's 2nd extra section without its 1st. Without this the solver could claim the high coverage of a first section while nominally opening a later one. {% if n_order == 0 %}On this data no course is short by more than one section's worth, so there are no second sections and this constraint is empty.{% endif %} {{ n_order | num }}
C3 Fairness cap per programme Σc∈p y_ck ≤ {{ maxprog if maxprog else 'M' }} {% if maxprog %}No single programme may absorb more than {{ maxprog }} of the extra sections, so one large programme cannot take everything.{% else %}Switched off — "Max per programme" is 0, so no programme limit is applied. Set it above 0 to turn this on.{% endif %} {{ n_prog | num }}
C4 Yes or no, nothing between y_ck ∈ {0, 1} Each candidate section is either opened (1) or not (0). You cannot open 0.6 of a section. This is what makes the model Binary Programming. {{ n_vars | num }}

What each symbol means

yck
decision variable — chosen by the solver
1 if the k-th extra section of course c is opened, 0 if not. There are {{ n_vars | num }} candidate sections, across {{ n_short | num }} short courses.
Uc
computed from the data
Unmet demand of course c before any extra section: max(0, Dc − cap × current sections). Total: {{ s.unmet_demand_before | num }} students.
ack
the objective coefficient
Students that section would seat, min(cap, remaining shortfall). It shrinks for later sections of the same course, so the last one is only part full.
B = {{ budget }}
parameter — chosen by the planner
Extra sections you can fund. Clearing every shortfall would need {{ s.sections_needed_to_clear_all }}.

Solving means choosing the set of y values that seats the most students while C1 to C4 all hold. The result cuts unseated students from {{ s.unmet_demand_before | num }} to {{ s.unmet_demand_after | num }}.
